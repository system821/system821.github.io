Spring知识集锦

  1. 什么是ioc容器

ioc容器是springboot的一部分 bean可以创建和管理应用程序所需的所有对象 ioc代表控制反转 不用手动new创建对象

ioc容器里面有很多bean bean直接通过@Autowire进行使用

@Component跟@Bean的区别
@Component直接放置在类上，Spring会自动检测到它并创建它的bean
@Bean则用于方法中，返回该类的对象
@Component是创建bean的一种简单方法

  1. spring 跟 springboot 区别
    springboot具有自动配置装置,spring则不是
    springboot内嵌了tomcat
    springboot支持H2数据库

  2. @SpringbootApplication 由 @EnableAutoConfiguration、@Configuration跟@ComponentScan 组成

  3. Diapatcher Servlet可以被视为任何Springboot应用程序的交通控制器/神经系统,因为所有的api请求都会先进入Dispatcher Servlet,然后决定那个控制器请求这个

  4. @Controller + @ResponseBody = @RestController

  5. bean的作用域：

  • singleton:在项目启动时创建的
  • protype
  • request
  • session
  1. 过滤器和拦截器
    过滤器是Serlet API的一部分，拦截器是Spring框架的一部分
    拦截器在@preHandler之后响应，在@afterCompletion()后返回给客户端
    拦截器的目的是：拦截到达调度程序serlet的请求，并在控制器方法之前和之后执行逻辑
    正确的执行逻辑是：Filter->DispatcherServlet->intercepton->Controller

  1. C/S架构跟B/S架构

    特点 C/S B/S
    部署方式 需要再每个客户设备上安装应用程序 只需使用Web浏览器
    更新与维护 每个客户端更新软件 主要在服务器端进行，用户访问的总是最新版本
    开发与兼容性 考虑各种操作系统和硬件平台 考虑不同浏览器的兼容性
    性能 提供更好的性能和响应速度 可能受到网络、服务器负载等影响
    可访问性 需要在特定的设备上安装 通过internet
    界面丰富度 可能提供更复杂和响应式的用户界面 依赖Web技术

    B/S工作原理：用户输入URL后Enter，① 浏览器缓存检查 ② DNS查询 ③ 简历TCP连接 ④ 发送HTTP请求 ⑤ 服务器处理 ⑥ 服务器响应 ⑦ HTTPS/TLS握手 ⑧ 渲染页面 ⑨ 加载其他资源 ⑩ 关闭TCP连接

  2. Spring MVC

    MVC各组件的分工：

    Model：代表应用程序的数据和核心业务逻辑，它响应视图和控制器的指令，如更新数据库、修改数据，通常包括数据访问层和服务层。

    View：负责展示数据，即用户所见的界面。它从模型获取信息并呈现给用户，处理用户界面和布局。

    Controller：处理用户请求，决定调用哪个模型组件，并将结果返回给用户。

    MVC架构的核心工作流程：

    (1) 用户交互

    (2) 控制器处理

    (3) 模型执行

    (4) 视图呈现

    (5) 用户响应

  3. Spring Boot项目包结构

    目录 描述
    com.example.myapp 项目的根包，以域名或公司名称的反转来命名
    controller 存放处理请求和响应的控制器类
    service 包含业务逻辑的服务类
    repository 数据访问和持久层，使用Mybatis-Plus等技术时可能命名为mapper或dao
    model 存放模型类，通常是POJO类
    config 存放配置类，用于配置应用程序的一些特殊设置：数据库连接、安全配置等
    dto 数据传输对象，controller和service层之间
    util 工具类

  4. 注解

    控制器注解

    @Controller和@RestController

    @Controller注解时，控制器类中的方法通常返回一个字符串，代表逻辑视图的名称

    @RestController是@Controller和@ResponseBody注解的结合体。它标记一个类为控制器，且类中的每个方法默认返回数据而非视图

    请求与响应

    参数绑定：@PathVariable、@RequestParam、 @RequestBody、@RequestHeader、@CookieValue

    全局异常处理

    @ControllerAdvice或@RestControllerAdvice和@ExceptionHandler

  5. 上传文件的注意点

    无论选择哪种方法存储文件，都需要确保以下内容。

    对上传的文件进行安全检查（如文件类型、大小等）

    使用随机和不可预测的文件名来保存上传的文件

    定期备份存储的文件

    实施适当的错误处理和异常处理机制

  6. 拦截器

    拦截器(interceptor)是一种设计模式，用于在某个操作或请求的前后插入特定的行为或处理逻辑。在Web开发中，拦截器通常用于在处理HTTP请求的前后执行某些操作，例如：

    身份验证和授权：在请求到达目标处理器之前，进行用户身份验证和权限检查。

    日志记录：记录请求的详细信息，如来源IP、请求的URL、请求方法以及响应时间和执行时长。

    数据处理与监控：预加载请求所需的数据，记录请求处理时间以进行性能监控，限制API使用频率等。例如，限制用户每分钟只能调用API有限次。

    在Spring Boot中，拦截器是通过实现HandlerInterceptor接口来创建的。此接口包含如下三个主要方法。preHandle()：在请求处理之前调用。如果返回true，请求继续进行；如果返回false，请求将中断。

    postHandle()：在请求被处理之后，视图被渲染之前调用。

    afterCompletion()：在请求处理完毕后调用，这包括视图的渲染。通常用于资源清理操作。

    (1) 自定义拦截器

    （2）在Springboot项目使用自定义拦截器

    在这个示例配置中：

    registry.addInterceptor(new CustomInterceptor())：将CustomInterceptor实例添加到拦截器注册表中。

    .addPathPatterns(“/api/**”)：指定拦截器应拦截/api/路径下的所有请求。

    .excludePathPatterns(“/api/auth/**”)：指定拦截器不应拦截/api/auth/路径下的请求。
